# 校园MHP平台 - Git 提交规则

## 一、适用范围

本规则适用于「校园MHP平台」项目的所有代码提交，包括但不限于：

- 后端 Java 代码（mhp-server、mhp-common、mhp-pojo）
- 配置文件（application.yml、nginx.conf等）
- 数据库脚本
- 文档文件（学习日记、接口文档、设计文档）
- 前端代码（前端相关文件）

## 二、提交信息格式规范

### 2.1 基本结构

```
<类型>(<模块>): <简短描述>

[详细描述]

[变更内容]
- <变更项1>
- <变更项2>

[关联信息]
- 相关文件: <文件路径>
- 解决问题: <问题描述/TODO编号>
```

### 2.2 提交类型（必填）

| 类型       | 说明     | 适用场景                                |
| ---------- | -------- | --------------------------------------- |
| `feat`     | 新增功能 | 新增接口、新增业务逻辑                  |
| `fix`      | 修复bug  | 修复代码错误、修复业务逻辑问题          |
| `docs`     | 文档更新 | 更新学习日记、接口文档、设计文档        |
| `style`    | 代码格式 | 代码格式化、注释调整（不影响功能）      |
| `refactor` | 代码重构 | 代码优化、重构（不新增功能、不修复bug） |
| `test`     | 测试相关 | 添加测试用例、完善测试覆盖              |
| `config`   | 配置变更 | 修改配置文件、环境配置                  |
| `chore`    | 杂项事务 | 构建脚本、依赖更新、工具配置            |

### 2.3 模块标识（必填）

| 模块          | 说明       | 示例                   |
| ------------- | ---------- | ---------------------- |
| `admin`       | 管理端相关 | 用户管理、角色管理     |
| `user`        | 用户端相关 | 用户登录、订单模块     |
| `common`      | 公共模块   | 工具类、常量类、异常类 |
| `properties`  | 配置属性   | JWT配置属性类          |
| `config`      | 配置相关   | WebMvc配置、JWT配置    |
| `interceptor` | 拦截器     | JWT拦截器、权限拦截器  |
| `mapper`      | 数据访问层 | SQL映射、MyBatis配置   |
| `service`     | 业务逻辑层 | 服务接口及实现         |
| `controller`  | 控制层     | REST API接口           |
| `util`        | 工具类     | JWT工具类、加密工具    |
| `entity`      | 实体类     | 数据库实体模型         |
| `dto`         | 数据传输对象 | 请求/响应DTO           |
| `vo`          | 视图对象   | 返回视图对象           |
| `docs`        | 文档       | 学习日记、接口文档     |
| `frontend`    | 前端       | Vue组件、页面、配置    |

### 2.4 描述规范

1. **简短描述**（必填）：不超过50字符，清晰说明本次提交的核心内容
2. **详细描述**（可选）：对变更进行详细说明，包括实现思路、技术选型等
3. **变更内容**（必填）：使用列表列出具体变更项
4. **关联信息**（可选）：相关文件路径、TODO编号、问题描述等

## 三、必填字段验证

### 3.1 强制要求

| 字段     | 要求               | 验证规则                                         |
| -------- | ------------------ | ------------------------------------------------ |
| 类型     | 必须在预定义列表中 | `feat/fix/docs/style/refactor/test/config/chore` |
| 模块     | 必须在预定义列表中 | 见2.3节                                          |
| 简短描述 | 非空               | 长度1-50字符                                     |
| 变更内容 | 非空               | 至少包含一条变更项                               |

### 3.2 格式验证

```
^(?<type>feat|fix|docs|style|refactor|test|config|chore)\((?<module>[a-z]+)\):\s+.+
```

### 3.3 错误处理机制

| 错误类型   | 错误信息                           | 处理方式               |
| ---------- | ---------------------------------- | ---------------------- |
| 类型错误   | "提交类型不正确，请使用预定义类型" | 拒绝提交，提示可选类型 |
| 模块错误   | "模块标识不正确，请使用预定义模块" | 拒绝提交，提示可选模块 |
| 描述为空   | "提交描述不能为空"                 | 拒绝提交，要求补充描述 |
| 描述过长   | "描述超过50字符，请精简"           | 警告提示，允许继续     |
| 缺少变更项 | "请列出具体变更内容"               | 拒绝提交，要求补充     |

## 五、提交示例

### 5.1 新增管理员登录接口

```
feat(admin): 新增管理员登录接口

【功能说明】
实现管理员登录功能，包含JWT身份验证、密码校验、用户信息查询

【变更内容】
- 新增 mhp-server/controller/admin/AdminController.java: 添加登录接口
- 新增 mhp-pojo/dto/AdminLoginDTO.java: 登录请求DTO
- 新增 mhp-server/service/AdminService.java: 登录方法声明
- 新增 mhp-server/service/impl/AdminServiceImpl.java: 实现登录逻辑
- 新增 mhp-server/mapper/AdminMapper.java: 登录查询方法
- 新增 mhp-server/resources/mapper/AdminMapper.xml: SQL映射

【技术要点】
- 使用MyBatis进行数据库查询
- 使用JWT生成登录令牌
- 使用BCrypt进行密码加密验证

【测试建议】
- 测试正常登录
- 测试用户名不存在
- 测试密码错误
```

### 5.2 修复MyBatis配置错误

```
fix(config): 修复MyBatis配置位置错误

【问题分析】
MyBatis配置被错误放置在spring节点下，Spring Boot无法正确读取配置，
导致Mapper接口与XML绑定失败，登录接口报500错误

【修复方案】
将mybatis配置从spring节点下移出，改为顶级配置

【变更内容】
- 修改 mhp-server/resources/application.yml: 调整mybatis配置位置

【验证方式】
- 启动服务查看MyBatis是否正常加载Mapper
- 测试登录接口是否正常返回
```

### 5.3 更新项目结构文档

```
docs(study): 更新项目结构文档

【概述】
更新项目结构文档，反映JwtProperties从server模块迁移到common模块的变更

【修改内容】
- 项目结构: 更新mhp-common模块结构
- 项目结构: 更新mhp-server模块结构

【关联信息】
- 相关文件: README.md或项目文档
- 解决TODO: 更新项目结构文档
```

## 六、特殊场景处理

### 6.1 TODO项关联

当提交涉及TODO项时，必须在提交信息中明确关联：

```
feat(admin): 完成JwtProperties配置迁移

【概述】
将JwtProperties从mhp-server/config迁移到mhp-common/properties

【变更内容】
- 新增 mhp-common/src/main/java/com/mhp/properties/JwtProperties.java
- 修改 mhp-server/util/JwtUtil.java: 更新import路径
- 删除 mhp-server/config/JwtProperties.java

【关联信息】
- 解决TODO: 将JwtProperties移到common模块
```

### 6.2 数据库变更

涉及数据库变更时，必须包含SQL脚本说明：

```
feat(mapper): 新增用户表索引

【功能说明】
为sys_user表student_no字段添加唯一索引，优化查询性能

【变更内容】
- 修改 sql/mhp_platform.sql: 添加CREATE UNIQUE INDEX语句

【SQL变更】
```sql
CREATE UNIQUE INDEX idx_student_no ON sys_user(student_no);
```

【影响范围】
- sys_user表数据写入性能略有下降
- student_no查询性能提升
```

### 6.3 配置文件变更

```
config(server): 更新Redis配置

【变更内容】
- 修改 mhp-server/resources/application.yml: 将spring.redis改为spring.data.redis

【注意事项】
- 适配Spring Boot 3.x配置规范
- 更新后需重启服务生效
```

## 八、版本控制规范

### 8.1 分支策略

| 分支类型 | 命名规范 | 用途 |
|----------|---------|------|
| 主分支 | `main` | 稳定版本代码 |
| 开发分支 | `develop` | 开发中的代码 |
| 特性分支 | `feature/xxx` | 新功能开发 |
| 修复分支 | `bugfix/xxx` | bug修复 |
| 发布分支 | `release/xxx` | 版本发布 |

### 8.2 提交频率

- 每个提交应只包含一个逻辑变更
- 避免一次性提交大量不相关的修改
- 复杂功能应拆分为多个小提交
